# P4 Completed: Browser Runtime

## Status

## Completed Capabilities

  - governed action-to-runtime mapping
  - cancellation checks
  - confirmation checks for write and high-risk actions
  - semantic-to-coordinate fallback handling
  - evidence event construction and publishing helpers

- Added `internal/browser/a11y.go`, `screenshot.go`, `coordinate_fallback.go`, and `confirmation.go`.
- Added an in-memory browser Evidence Bus implementation for deterministic tests.
- Added local browser fixture pages under `internal/browser/testdata/browser`.

## Configuration

P4 adds a mountable config-file value for local screenshot output:

```yaml
browser:
  enabled: true
  runtime: chromedp
  screenshot_dir: ./data/browser/screenshots
  profile_reuse:
    enabled: false
    profile_dir_env: PERSONAL_AGENT_BROWSER_PROFILE_DIR
    allowed_domains: []
    session_ttl: 8h
```

The chromedp runtime accepts allocator options from callers. Browser executable paths, remote CDP endpoints, profile directories, URLs, credentials, and tokens are not hardcoded.

## Validation

```sh

```

P4 tests cover runtime adapter behavior, confirmation gating, evidence publishing, session reuse policy, coordinate fallback, semantic locator behavior, domain allowlist denial, profile-store environment lookup, and opt-in local browser E2E skipping.

To run the real local browser fixture:

```sh
PACHAT_BROWSER_E2E=1 go test ./internal/browser
```

## Known P4 Boundaries

- CLI task execution still does not automate the browser.
- Browser permissions are still package-local policy and confirmation boundaries; the global P5 permission layer is not implemented yet.
- Browser evidence uses an interface plus in-memory implementation; storage-backed evidence integration remains planned.
- Cookie reading and password reading are intentionally not implemented.
- Verification, cost accounting, REST APIs, and full local E2E remain planned for later phases.
