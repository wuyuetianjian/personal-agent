# P9 Core Release Slice Completed

## Status

P9 core release slice completed locally on 2026-09-06.

## Completed

- Added `docs/p9_core_release_slice.md` as the scoped P9 design and acceptance document.
- Added `internal/capability` with capability kinds, health states, registry, deterministic resolver, trust/privacy/cost/side-effect filters, and tests.
- Registered local Memory, RAG, Browser, Verification, and configured Coding Agent backends as Runtime capabilities.
- Added `internal/skill` with versioned manifests, YAML loading, dependency validation, permission/trust escalation checks, registry activation, and skill-first matching.
- Added `internal/workflow` with persistent workflow/node state, lifecycle transitions, checkpoints, recovery queries, idempotency keys, and side-effect metadata.
- Added `internal/project` with SQLite-backed project context and allowlist policy.
- Added `internal/mcp` with read-only server/tool metadata and MCP-to-Capability adaptation; external transports and credential loading are intentionally out of scope.
- Added SQLite migration `0002_p9_core.sql` for projects, skills, workflow runs/nodes, and checkpoints.
- Added CLI commands for capability listing/health inspection and workflow list/show/pause/resume/cancel.
- Updated English and Chinese README sections.

## Validation

```sh
go test ./...
```

All three commands passed for this increment. New tests cover capability filtering, Skill validation/matching, MCP adaptation, Project round trips, Workflow checkpoint/recovery, lifecycle transitions, and CLI capability/workflow commands.

## Boundaries / Next Steps

- A full background worker and automatic restart loop are not included yet; the persisted state and recovery query are ready for that integration.
- Skill matching and Workflow compilation are library boundaries; Skill execution is not yet wired into the Scheduler.
- MCP is metadata-only in this slice; a real stdio transport, tool call sanitization, and evidence persistence remain follow-up work.
- P8 Codex/Claude execution remains governed by `internal/codingagent`; P9 only registers configured backends as capabilities.
- Capability metrics/evaluation suites and full workflow REST APIs remain subsequent P9 increments.
