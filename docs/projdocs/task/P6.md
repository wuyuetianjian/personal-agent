# P6 Completed: API, E2E, And Hardening

## Status

Completed locally on 2026-09-06.

## Completed Capabilities

- Added `internal/api` with:
  - local REST handler using the standard library
  - task create, list, status, cancel, and event listing endpoints
  - confirmation inspect, approve, and deny endpoints
  - JSON responses with stable HTTP status codes
  - API-facing redaction for secret-like title, final answer, event, and confirmation fields
- Extended `internal/permission` confirmation store with:
  - deny support
  - explicit pending, approved, and denied status reporting
  - unchanged `IsApproved` behavior for existing confirmation gates
- Added `internal/e2e` with:
  - full local-first integration test using provider mocks, SQLite, RAG, episodic memory, semantic memory, browser high-risk denial, verification, cost accounting, and API event reads
  - secret-leak regression fixtures for API responses, Privacy Gateway output, and browser evidence
  - PostgreSQL integration placeholder that skips cleanly when no DSN is configured
- Hardened task creation so running tasks no longer receive a completed timestamp.

## API Surface

Implemented endpoints:

```text
POST /tasks
GET /tasks
GET /tasks/{id}
POST /tasks/{id}/cancel
GET /tasks/{id}/events
GET /confirmations/{id}
POST /confirmations/{id}/approve
POST /confirmations/{id}/deny
```

The API package exposes a handler boundary only. P6 does not add a packaged long-running HTTP server command.

## Configuration

P6 does not add new hardcoded runtime configuration. API tests use local test inputs, temporary SQLite paths, in-memory event buses, and in-memory confirmation stores. PostgreSQL testing is gated by `PACHAT_POSTGRES_TEST_DSN` and skipped when unavailable.

## Validation

Run:

```sh
go test ./...
make build
make smoke
```

P6 tests cover REST task lifecycle, confirmation approve/deny, event listing, full mock-based local integration, browser high-risk denial, and secret-leak regression behavior.

## Known P6 Boundaries

- P6 remains local-first and mock-backed for integrated agent execution.
- The REST API is available as `internal/api` handler wiring, not a standalone server CLI command.
- CLI task execution still does not run the full RAG/browser/Sub-Agent/verification pipeline.
- PostgreSQL runtime support remains represented as a cleanly skipped integration placeholder until the storage connector is implemented.

## Next Phase

P0-P6 are complete locally. A future phase should wire the library-level capabilities into real task execution and choose whether the HTTP API should become a supported server command.
