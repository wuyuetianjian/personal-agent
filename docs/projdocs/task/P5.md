# P5 Completed: Permissions, Verification, And Cost

## Status

Completed locally on 2026-09-06.

## Completed Capabilities

- Added `internal/permission` with:
  - global permission action categories
  - configurable default decisions and per-action overrides
  - deny-by-default high-risk behavior
  - confirmation request creation with target, risk, evidence, and exact proposed effect
  - in-memory confirmation approval flow for tests and later API wiring
  - auditable permission decision records
- Added `internal/verification` with:
  - deterministic claim extraction from structured text
  - claim/evidence coverage evaluation
  - conflict detection between claims and evidence
  - confidence policy evaluation for final synthesis gates
- Added `internal/cost` with:
  - budget and usage record types
  - registry/config-backed pricing lookup
  - model usage cost estimation
  - soft and hard limit enforcement

## Configuration

P5 keeps runtime values configurable through the existing config and registry flow. Model pricing is read from model metadata loaded from config. Permission defaults continue to come from mountable config:

```yaml
permissions:
  default: deny
```

No provider prices, secrets, URLs, credentials, or environment-specific values are hardcoded in P5 source code.

## Validation

Run:

```sh
go test ./...
make build
make smoke
```

P5 tests cover permission policy decisions, confirmation approval, audit records, claim extraction, evidence coverage, conflict detection, confidence policy, pricing lookup, usage estimation, and budget soft/hard limits.

## Known P5 Boundaries

- P5 is implemented as library-level packages.
- CLI task execution still does not enforce the global permission evaluator, verify final answers, or meter live model calls.
- Storage-backed permission decision persistence remains represented by existing migrations and deferred wiring.
- REST/API confirmation endpoints and full local E2E remain planned for P6.
